### Why A-07 has a star

The standard way this feature ships broken: the save effect fires once on mount with the *empty* initial
state and overwrites everything you had. It looks fine in testing right up until you have data worth
losing. The provider guards it with a `hydrated` ref, and A-07 is what proves the guard works.

## 5. Deleting now asks first

Deleting used to be free — a refresh wiped everything anyway. Now it destroys real history, and there is
no undo.

| ID | What to check | How | Expected | Who | Status | Notes |
|----|---------------|-----|----------|:---:|:------:|-------|
| A-18 | First tap arms, does not delete | Tap **×** on a habit | The × becomes a red **Delete?** pill. **The habit is still there** | 🤖 | ✅ | |
| A-19 | Second tap deletes | Tap the **Delete?** pill | Habit is removed, and stays removed after a reload | 🤖 | ✅ | |
| A-20 | Tapping the row cancels | Arm a delete, then tap the habit's title | Back to the plain × | 🤖 | ✅ | |
| A-21 | Cancelling does not tick the habit | Same as A-20, watch the checkbox | Stays unchecked — the cancel tap is swallowed | 🤖 | ✅ | Easy thing to get wrong |
| A-22 | Auto-disarms | Arm a delete, wait ~4 seconds, don't touch anything | Reverts to × on its own | 🤖 | ✅ | **Is 4 seconds right for you?** See below |
| A-23 | Confirm target is big enough | — | Pill is 44px tall | 🤖 | ✅ | |
| A-24 | Screen reader says what's at stake | Inspect the pill's `aria-label` | "Confirm deleting X **and its whole completion history**" | 🤖 | ✅ | |
| A-25 | Feels right in the hand | Delete a few things on your phone | Not annoying, not too easy to trigger by accident | 👤 | ⬜ | **Your call** |

### One thing to judge: the 4-second timeout

I picked 4 seconds for the auto-disarm. It is long enough for a deliberate second tap and short enough
that a stray arm does not sit there indefinitely. It also means if you get distracted mid-delete you have
to start again — which fails safe, but might feel short. Easy to change; say a number.

## What Block A built

- **`lib/storage.ts`** — the whole boundary. Versioned envelope, field-by-field validation, a `migrate()`
  seam for the next schema change, quarantine of anything unreadable, and no path that throws.
- **`store/reducer.ts`** — one new `HYDRATE` action.
- **`store/HabibitProvider.tsx`** — loads before paint, saves after every change (guarded), and listens
  for other tabs.
- **`components/ui/ItemRow.tsx`** — the two-tap delete.
- **`components/layout/SaveWarning.tsx`** — only appears if a write genuinely fails.
- **`lib/storage.test.ts`** — 13 tests using an in-memory `Storage` stub, so the suite still needs no
  `jsdom` and stays a pure node run.

### A risk from the plan that resolved itself

The plan flagged that React 19's `react-hooks/set-state-in-effect` rule — which rejected a pattern back in
Block 1 — might also reject dispatching from the hydration layout effect, and that the fallback would be a
documented `eslint-disable`. **It did not fire.** Lint is clean with no suppressions anywhere in the
codebase.

### Deviations from the approved plan

| Plan said | Actually did | Why |
|---|---|---|
| Confirm cancels "on a timeout or tapping elsewhere" | Timeout, tapping the row, **or the button losing focus** | Focus loss was free to add and covers keyboard users tabbing away |
| — | Added `lib/useIsomorphicLayoutEffect.ts` | The layout-effect-vs-SSR swap deserved its own named file rather than being inlined in the provider |
